## 实现与适用范围

本轮把先前的无预哈希实验接入客户端，不替换默认兼容路径。
发送页选择一个普通文件后可显式打开“快速发送（实验）”，默认关闭、每次发送重新选择。
只面向运行兼容新版的已配对设备，单文件上限 8 GiB。

流程为：

1. 用户先选择已配对目标，在当前CONTROL连接以750ms有界查询确认其源流式能力及TLS身份；
   官方、旧版或未知能力只进行一次legacy准备，不先发新票据再重发。
   对支持快速模式的目标，在已经运行的设备节点注册一个打开的源文件，生成随机256-bit capability。
   不完整读文件、不导入 blob store、不提前计算完整 hash、不另建发送 endpoint。
2. 通过原有配对控制通道邀请目标设备。票据携带有限文件信息供本地预览；它是非可信提示，
   真正的文件信息以连接后 Offer 为准。
3. 接收端复用自身的设备 endpoint，建立独立 STREAM 连接；发送端在握手及每次新请求时
   检查当前配对/阻止状态。控制通道仍使用原策略。
4. 有界帧、背压与增量校验直接写入最终目标文件系统的私有临时文件；校验完成后提交实际文件名，
   最终导出成功才触发完成、历史、通知与复制入口。
5. 停止共享只撤销对应注册；停止接收只关闭本次 STREAM 连接，不关闭常驻设备节点。
   网络重建撤销旧节点代的票据，不静默迁移、重试或重复发送。

发送端最多 16 个源文件注册、4 个握手后的活动 STREAM 会话，第五个不排队。
Router 负责握手任务；这个数值不是握手并发限制。进度按 100 ms 限流，避免逐帧 UI 事件。
发送终态 guard 使取消、超时及 Router abort 不会把已开始的历史记录永远留在“传输中”。

## 明确未覆盖

- 多文件、文件夹、文字、浏览器、QR、Nearby/未配对设备、广播和 Flash Drop 保留 legacy。
- Android SAF 仍先复制到本地暂存；此路径只消除后续 blob 导入/预哈希，未实现直接读 URI descriptor。
- 无断点续传或自动重试；已加入邀请前旧端能力协商。源文件在传输中必须保持不变。
- 没有加入中继磁盘spool，也没有修改生产中继或解除传输完整性校验；Iroh随官方0.7.2升级至1.3.0。
- 前面的模拟数据面 benchmark 不是本次 GUI 的端到端时延保证，不承诺所有网络三秒内开始传输。
