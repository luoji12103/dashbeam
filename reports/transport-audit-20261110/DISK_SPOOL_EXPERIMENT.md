# 硬盘滑窗真实请求实验

2026-11-10，Debian13 DEV。实验源码 [disk_spool_probe.mjs](disk_spool_probe.mjs)，原始输出 [disk-spool.jsonl](disk-spool.jsonl)。这是新协议机制的小原型，不是 DashBeam 产品补丁，也不是已具备生产持久化语义的服务器。

## 做了什么

在 `127.0.0.1` 随机端口建立真实 HTTP 连接，以 POST 上传和独立 GET 下载流连接同一个临时 spool。读取真实合成磁盘文件，以每帧最多 64 KiB 的 AES-256-GCM 密文传输；每任务随机密钥、临时认证口令与传输标识，不访问生产配置、配对设备或用户文件。认证AAD绑定实验传输/epoch/file/frame/明文长度，帧序号构造唯一nonce。

服务器按帧写入独立文件并 `fdatasync`，首帧写成后立即供下载，不等文件完成或20%窗口填满。接收者逐帧验证tag、写出真实目标文件并 `fdatasync` 后，通过另一条 HTTP 请求确认这一帧；服务器删除对应磁盘文件后才归还 credit。窗口满则暂停消费上传流，将反压传到发送方；应用和内核仍有小型有界网络缓冲。

帧缓存以文件系统块分配计费：一帧64 KiB加tag及头，向上预留到4 KiB边界（69,632 B），并用实际 `stat.blocks*512` 检查没有超过预留。原型的预算是**帧数据文件块预算**，没有将目录、inode、journal和完整恢复索引纳入；最终设计的严格总配额需要为这些另行预留，因此这里的成功不能证明完整spool实现已满足总磁盘上限。

源文件在计时前创建并sync；从开始建本次临时监听/HTTP连接到首帧认证，全部使用同一DEV进程的单调时钟，不存在跨设备时钟相减。基于实际读到的内容增量计算SHA-256，完成后核对字节数和摘要。该摘要核对由同一实验runner完成，不是最终设计的跨端签名manifest实现。

## 实测

单轮机制验证，非p95或稳定性能分布。2026-11-10 09:30 UTC。第三行用接收程序节流为4 MiB/s，真实数据仍通过socket与磁盘；这是人为制造速率不匹配，没有模拟公网RTT或丢包。

| 源大小 / 场景 | 首认证文件帧 | 全部接收完成 | 帧磁盘块峰值 / 20%预算 | credit等待 |
| --- | ---: | ---: | ---: | ---: |
| 1 MiB，不限速 | 29.57 ms | 69.03 ms | 208,896 / 209,715 B | 2次，合计1.34 ms |
| 32 MiB，不限速 | 7.37 ms | 840.03 ms | 348,160 / 6,710,886 B | 0次 |
| 32 MiB，收端4 MiB/s | 6.13 ms | 8,006.27 ms | 6,684,672 / 6,710,886 B | 406次，合计5,638.24 ms |

三种场景均字节数与SHA-256匹配，结束时窗口占用归零。第三种在6,508.44 ms时上传流才完成，接收在8,006.27 ms完成，说明缓存吸收了部分速率差，但发送方仍会被慢收端反压。首帧没有等32 MiB全部读完，也没有等待缓存攒到20%。

1 MiB的第一轮包含Node/HTTP/加密等冷执行成本，不能从两行对比得出“大文件比小文件更快”。这组实验只确认机制成立：首帧路径不再依赖完整文件hash或全文件落盘。它不能预测中国移动网络、跨GZ/SH、公网代理、Android SAF和手机后台的延迟。

## 持久化与安全边界

- 原始JSON中的 `first_server_disk_durable_ms`、`first_receiver_durable_ack_ms` 和 `frames_durable_acked` 是实验阶段名称：这里只证明帧文件/目标文件执行了data sync，**没有持久化目录项与一致性checkpoint，也没有崩溃恢复journal**。不能解释成最终协议的 UPLOAD_DURABLE / RECEIVER_DURABLE 保证。
- 没有持久化授权、签名ACK、撤销/重放日志、配额并发准入、多租户隔离或最终manifest协议；单任务共享runner提供身份和摘要，不等于产品E2EE实现已经审计。
- 只监听DEV回环，临时认证口令不输出，外层没有TLS；不能按此方式对公网部署。
- 未测试ENOSPC、进程死亡、重启恢复、恶意帧、不同文件系统分配单位和服务端无法证明真实free-space的场景。最终设计中的这些门槛仍有效。

## 复现与清理

DEV目录 `/home/luoji/code/dashbeam-disk-spool-probe-20261110`；Node内置库，不安装依赖。运行 `timeout 60s node disk_spool_probe.mjs > disk-spool.jsonl`。每次创建约32 MiB合成源与目标、临时回环服务；正常退出关闭全部连接并删除临时数据，仅保留脚本与脱敏结果。实验没有常驻daemon、systemd或生产入口。
