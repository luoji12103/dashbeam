# 官方同步与兼容策略

本仓库是 `tonyantony300/dashbeam` 的定制 fork，保留 AGPL-3.0，持续合入官方更新，
同时保留本地的菜单栏、Finder Share、文字/剪贴板、通知复制和低延迟传输改进。
“升级官方基线”不是把应用替换成未定制的官方二进制。

## 当前开发基线

- 官方稳定版：v0.7.2，tag `e535ceaa6e7ee619c1ab12345cb277b7136fbed5`。
- 已完整合入的官方 main：`c5de16552fc946ec9d0ad3b3792875868e826a05`。
- 官方网络依赖：Iroh 1.3.0、iroh-blobs 0.103.1、rustls 0.23.45。
- 拟发布定制版本：`v0.7.2-local.1`，Mac/Android build 70201；只有实际发布后才视为可下载版本。

## 每次跟随官方升级

1. 拉取并核实最新官方稳定 tag 与 main，保存工作树中的未完成工作，不覆盖并发修改。
2. 在定制分支合入完整官方提交历史，不只改显示版本或任意更新全部依赖。
3. 人工整合冲突；保留本地接收导出路径验证、配对/凭据边界、取消和并发保护。
4. 同步产品版本、本地递增 build、分享扩展版本与打包产物；保留历史 release 链接。
5. 执行自动回归与官方原样引擎双向互通测试；网络库更新后重跑实际安装版传输。
6. 冻结同一产品源码后构建各平台包，保持原定制应用身份和签名以便原位升级。
7. 发布明确标识 `-local.N` 的定制 release、校验和、变更和未验收边界。

当前禁用定制包的官方二进制自动覆盖入口，以防丢失功能。这里不表示停止跟随官方，
也不表示已经实现定制 release 的自动下载更新器。

## 互通边界与发布门槛

普通文件继续使用官方 BlobTicket/控制协议；新增能力应为可选字段，不能修改旧消息类型、
ALPN 或配对签名材料。快速流式发送必须在邀请前确认当前连接的对端能力；
官方/旧端/未知能力应走一次 legacy 准备及邀请，不能先发新票据再失败重发。

双向普通文件、空文件、多文件、冲突改名、配对邀请、取消后的再次收发，以及新版本间的快速模式，
均应进入回归范围。声明“已兼容”须写明实际测试的官方版本和路径，不能承诺所有历史/未来版本。

文字可向旧官方客户端作为普通 `.txt` 文件发送；未修改的官方客户端不会凭空出现文字面板或自动复制功能。
新增文字接收面板、通知动作等功能只在支持它们的定制客户端中生效。
